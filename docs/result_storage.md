# 实验结果的轻量保存

用户要求（2026-10-15）：后续新实验最终只用 **Excel + 报告** 保存结果。工作流程见本机技能 [save-experiment-results](/home/zyd/.codex/skills/save-experiment-results/SKILL.md)，可通过 `$save-experiment-results` 调用；在 `~/code` 下新增、修改或整理实验结果时默认遵循。

## 新实验的目标格式

```text
results/<experiment>/<run>/
  results.xlsx
  REPORT.md
```

工作簿保存配置、实际预算、逐样本或逐请求测量、汇总指标、失败与未验证状态、单位、样本数、来源哈希和最终清理凭据。报告说明问题、方法、实际结论和局限，并引用工作簿。同一 run 更新固定文件，避免不断积累报告副本；不同 run 分开保存。高频日志采用有界内存流式汇总，明确统计口径和未保留的明细；缺测不能填成零或改写为通过。

不长期另存视频、张量、latent、逐事件日志或默认预览文件，也不将它们压缩后塞进 Excel。原始数据只作为实际评测、盲评、续跑或故障调查的临时输入。依赖关闭后，先回读校验工作簿和报告、核对来源哈希，再按明确文件清单清理。删除前保留可恢复收尾状态的日志，完成后把最终凭据纳入工作簿/报告。移动到 `.cache` 不等于释放空间，统计和收尾需覆盖临时工作目录。

新增实验入口需要同时实现导出及依赖关闭后的收尾；仅调用现有 export hook 或修改配置声明并未完成此约定。工作簿生成、完整哈希和重型汇总应在被计时的 GPU 路径之外执行。本技能是后续实现与操作的工作约定，不是后台清理服务，也不改变运行中的冻结实验。

## 依赖和历史兼容

运行中、待评测、待盲评和待续跑的真实输入必须保留。账本空闲或存在阶段报告不等于依赖已关闭；应核实每个候选文件的实际使用者。父研究因其他阶段尚未开始而未完成时，无依赖的已完成子结果可以单独归档，原有失败、未完成和语义未评判状态保持不变。

删除原始数据后只可查阅历史指标，不能重算图像质量、生成新的盲评窗口或恢复原始状态；必须标明 `retained_metrics_only`，不能把归档校验说成重新评测。不得修改历史结果、预算、冻结配置、源码或来源绑定来通过检查。模型和必要 GPU 运行库不属于实验结果，不能跨符号链接清理。

现有报告 hook `ditserve.result_storage.export_report` 只导出，复用 `excel/`，不会删除原始文件。`configs/result_storage.json` 中部分字段只声明目标，并未自动实现盲评、续跑依赖判断。当前旧格式仍需要 Excel 配套的 `data.json.gz`、`manifest.json`，清理后还需要 `pruned.json` 和源目录 `.compact-results.json`，以及被现有读者引用的小型元数据和冻结来源。这些是兼容例外；安全迁移读取及校验逻辑前不能只为凑成两文件而删除。

通用归档的 gzip 保存完整小文本和超出工作簿展示上限的字段，不是可随意清理的缓存。大型 JSON/JSONL 默认仅登记哈希，需要另行生成并校验流式摘要才能清理。带删除凭据的归档不能覆盖；仍在刷新报告的目录应在首次清理前选择独立 `.retention/<唯一归档名>` 保存不可变归档。已有归档不能直接移动；迁移需保留完整凭据、校验副本、更新定位记录并验证缺失来源引用。

`PYTHONPATH=python python3 -m ditserve compact-results results/<已审核的封闭run> --prune-raw` 可对无活动和后续依赖的具体目录执行导出、回读校验与原始数组清理。它会选择包括 `.pt/.pth/.safetensors` 在内的 raw 后缀文件，不能套用于整个 `results` 或混有模型和待评测数据的目录。省略清理选项只导出；部分清理使用显式文件白名单。各调度和优化接口的真实收尾能力见技能的 [项目参考](/home/zyd/.codex/skills/save-experiment-results/references/dit-rewrite.md)。
